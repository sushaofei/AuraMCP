# 数据库查询与分析

`database` 扩展提供 `auramcp.database.describe` 和 `auramcp.database.query`。
AuraClaw 通过既有 Action Hands 与 Credential Proxy 调用；Runtime 和 AuraX 不直连数据库。
服务负责查询真实数据，任务理解、指标解释和回答继续由 AuraClaw 执行。

## 输入与范围

先调用 `describe` 获取表别名、允许字段、类型、注释和单位。调用者只能传表别名、列名、
筛选、分组、聚合、排序和结果上限。连接目标和原始 SQL 不属于工具参数。

```json
{
  "table": "records",
  "filters": [{"column": "created_at", "operator": "gte", "value": "2026-10-01T00:00:00"}],
  "group_by": ["area"],
  "aggregates": [{"function": "count", "alias": "count"}],
  "order_by": [{"column": "count", "direction": "desc"}],
  "limit": 20
}
```

`columns` 用于明细；`group_by` 与 `aggregates` 用于统计，二者不混用。
聚合支持 count/sum/avg/min/max。筛选以 AND 连接，支持 eq/ne/gt/gte/lt/lte/contains/is_null；
contains 匹配字面子串，输入中的 `%` 和 `_` 不扩展为 SQL 模式。时间输入为 ISO 格式，
无时区字段不接受带时区的时间值。金额保留数据库精度和字段注释中的原单位。
字段注释是来源元数据，不代表业务口径已经校准；需要解释金额时应说明来源，不猜测或静默换算。

每次最多 200 行、12 个筛选、4 个分组字段。查询默认 5 秒、连接池最多 2 个连接，
数据事务与连接默认只读。结果行截断和单元格文本截断分别显式标记；数据行字节上限
128000，文本单元格上限 4000 字符。大整数与 Decimal 使用字符串，避免浏览器丢失精度。
结果不会为了获取总行数再扫描整个表。业务错误不向 Agent 返回连接信息或数据库错误原文。

## 独立数据配置

`AURAMCP_DB_*` 只用于治理库。能力配置由 `AURAMCP_ANALYTICS_CONFIG_FILE` 指向受保护 JSON：

```json
{
  "host": "database.internal",
  "port": 5432,
  "database": "authorized_database",
  "user": "application_user",
  "password_file": "/run/secrets/db_password",
  "ssl": "require",
  "allowed_tenants": ["tenant-a"],
  "allowed_users": ["user-a"],
  "statement_timeout_ms": 5000,
  "tables": [{
    "alias": "records",
    "schema_name": "reporting",
    "table_name": "authorized_records",
    "columns": ["id", "area", "created_at"],
    "default_columns": ["id", "area"],
    "default_order": "id",
    "description": "已授权的分析数据；字段单位在数据库注释中维护。"
  }]
}
```

配置不入 Git，密码仅从受保护文件读取。调用时同时核对可信租户与用户，失败时连表结构也
不返回。数据库侧另按实际表/列授予 SELECT，不授予写入、建库或建角色权限。
服务账号可以沿用统一应用账号，能力连接与治理连接仍分别配置。

启动时核对所有配置字段实际存在；缺列会拒绝启动，避免目录显示可用但调用才发现错配。
关闭时分别释放能力连接与治理连接。

## 部署及验收

`deploy/Containerfile` 要求显式提供已核验的 Python 镜像 digest；`deploy/requirements.lock`
从仓库 uv.lock 冻结导出，安装校验包哈希。构建上下文排除环境文件、缓存与 Git 数据。
`deploy/compose.yml` 运行非 root、只读根、资源限制的独立服务，入口仅绑定 loopback，
只加入受控内部网络。治理库及网络须预先准备，镜像以核验过的本地 ID 指定。

部署必须配置真实 workload 凭据、可信身份与独立管理员凭据，保持
`AURAMCP_ALLOW_INSECURE_IDENTITY=false`。MCP 注册只传 credential_ref，不传凭据正文。
当前 MASTER2 是开发工作台，凭据供应方式须在运维配置中明确；不将开发内存 Vault
声称为生产密钥管理。启用真实数据前核对来源、访问范围和凭据存放授权。

验收依次覆盖：直接 MCP 字段发现与只读查询、越权库表和写请求拒绝、金额/日期类型、
查询超时与结果截断、AuraClaw 目录发现和真实 Hands 调用、AuraX 自然语言分析及轨迹显示。
库表名称、连接地址、查询数据和凭据仅保留在私有部署记录，不发布到公开 issue。

停止与回滚先禁用 AuraClaw MCP 注册，再停止新服务；恢复 Credential Proxy 原配置，
保留治理审计与验收证据。业务表不进行数据迁移或内容改写。

## 首次部署验收（2026-10-27）

已按明确授权部署独立 AuraMCP，治理连接与指定业务数据源分离，沿用统一应用账号。
业务连接实测为只读，允许业务字段可读，未授权的联系人列和 INSERT/UPDATE/DELETE 均拒绝。
真实 Hands 链路通过字段发现与明细查询；五条记录的分组计数和 Decimal 汇总与明细一致。
Credential Proxy 重启后已验证连接及凭据引用恢复。

AuraX 已登记并展示只读数据库能力，真实自然语言任务完成并保留执行轨迹与结果。
同时修复配置编辑误判私网 DNS、覆盖既有准入策略，以及恢复终态对话时重复显示流式片段的问题。
私有部署记录保存源码/依赖/镜像指纹、数据范围、权限及联调回执；业务数据和连接配置不入库。

本地按 uv.lock 安装独立 Python 3.11 环境：51 项测试、Ruff、Mypy 45 个源文件和六条架构合同通过。
实际运行镜像通过非 root 导入和健康检查；冻结依赖哈希在构建时校验。
