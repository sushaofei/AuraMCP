## Phase 1 — 标准 MCP Front Door + Builtin

- [x] `POST /mcp`：discover / list / call / read / get
- [x] 规范 `_meta`（`io.modelcontextprotocol/*`）与规范 MCP Header
- [x] Builtin ping / echo / about Resource / usage Prompt
- [x] 协议错误走 JSON-RPC Error；业务错误走 `isError=true`
- [x] 未知 method 按规范返回 `-32601`，不提供私有替代方法
- [x] 文档按「标准 MCP Server」陈述，而不是私有 RPC

## Phase 2 — AuraClaw 专用身份与 ACL（保留）

- [x] Hands workload
- [x] trusted context 与 `_meta.io.auraclaw/*`

- [x] 生产禁止 insecure identity
- [x] 源码不含 chaintower / auraclaw 内部包引用
- [x] 身份保持在传输层：不把 `io.auraclaw/*` 或 `X-CT-*` 变成 MCP 方法 params

## Phase 6 — 数据库查询与分析

- [x] 可选数据库扩展：字段发现、受限明细查询和分组统计；生产入口默认不启用。
- [x] 独立能力连接配置；租户/用户、表/列白名单；不接收 SQL 或连接目标。
- [x] 数据事务只读、参数化值、超时/行数/字节限制、金额与时间保真及错误脱敏。
- [x] 标准 MCP 合同、参数与权限拒绝、连接关闭、超时及截断回归通过。
- [x] 类型检查、静态检查与六条架构边界通过，治理库不承载能力数据。
- [x] 冻结依赖、独立容器部署文件和凭据文件读取准备完成。
- [x] 远程部署准入：治理库创建、只读权限配置与凭据保存取得明确授权。
- [x] 指定真实数据源验证、AuraClaw 注册与真实 Runtime 调用、AuraX 联调完成。
- [x] 重启后凭据引用恢复、真实分组/金额汇总及联系人列拒绝验证通过。
- [x] 部署回执、清理和最终阶段状态完成；终态对话恢复实测仅一份可见正式回答，无重复流式片段。
