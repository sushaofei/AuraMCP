# 扩展包开发

一个目录就是一组 Tool / Resource / Prompt。新增能力只改 AuraMCP，不改 AuraClaw Runtime。

## 步骤

1. 在 `src/auramcp/extensions/<name>/` 声明 schema 与 handler。
2. 名称必须使用 `auramcp.` 前缀，Resource URI 必须使用 `auramcp://`。
3. 在 `composition/app.py` 的 `build_runtime` 里注册到 `packages`。
4. 启动时 Catalog 计算 digest；canonical_name 冲突会拒绝启动。
5. 用合同测试覆盖标准 MCP 方法：`server/discover`、`tools/list`、`tools/call`（以及需要的 read/get）。不要为扩展发明规范外 JSON-RPC 方法。

## 存储分离（硬约束）

- `AURAMCP_DB_*` 只保存平台治理数据：扩展开关、Catalog 发布、审计。
- **不要**把该能力的领域表建进平台库，也不要复用 `AURAMCP_DB_*`。
- 能力若需要持久化：新增独立环境变量 / DSN，并在该扩展目录写明。

`builtin` 与 `ops` 都不读写能力业务行；`ops` 只读平台治理状态。

## 当前扩展

| 包 | 能力 | 存储 |
|---|---|---|
| `builtin` | `auramcp.health.ping`、`auramcp.example.echo`、`auramcp://builtin/about`、`auramcp.example.usage` | 无 |
| `ops` | `auramcp.ops.catalog_snapshot`、`auramcp://ops/handbook`、`auramcp://ops/extensions/{name}`、`auramcp.ops.diagnose` | 只读平台治理库，无能力表 |
